이제 '내 것'으로 만들 차례.

이 프로젝트에서 코드와 설정의 많은 부분을 Claude가 처리했어요. 발표와 운영에서는 "왜 이렇게 만들었는지"를 민찬이 직접 설명할 수 있어야 합니다. 무엇을 공부하면 되는지 순서대로 정리했어요.

작업 기록을 기준으로 나눠 봤어요. 오른쪽 일은 앞으로 민찬이 점점 가져와야 합니다.

민찬이 한 일방향을 정하고 확인했어요
  • 아이디어와 기획안 제공
  • "실제 작동 웹앱", "Firebase + GitHub Pages" 같은 방식 선택
  • GitHub 저장소 만들기, 계정 연결, 앱 설치
  • 배포 상태 확인(주황색=대기 발견), 실제 작동 확인
Claude가 대신한 일 → 민찬이 이해할 일코드와 설정, 문제 해결
  • 앱 코드 740줄 작성 → 한 함수씩 읽고 설명하기
  • Firebase 설정, 보안 규칙 → 규칙을 한국어로 해석하기
  • 배포 오류 진단과 해결 명령 → 왜 그 방법이 통했는지 말하기
  • 포인트·티어 계산 로직 → 숫자를 바꿔 결과 예측하기

핵심: AI가 만들어 준 것을 쓰는 것과, 이해해서 내 것으로 쓰는 것은 달라요. 발표 질문은 거의 후자를 묻습니다.

10가지 배움

내 수준을 눌러서 표시해 보세요.

정직하게 고를수록 좋은 계획이 나와요. 이 기기에 저장됩니다.

0 = 아직 몰라요 · 1 = 들어봤어요 · 2 = 설명할 수 있어요 (친구에게 3분 안에 설명 가능한 상태)

지금 먼저 할 것

    4주 계획

    읽기 → 고치기 → 만들기 → 설명하기.

    1주차 · 읽고 이해하기

    목표: 우리 앱이 어떻게 돌아가는지 그림으로 그릴 수 있다.

    1. index.html을 위에서부터 읽으며 모르는 줄에 표시모르는 줄은 Claude에게 "이 줄이 뭘 하는지 초등학생에게 설명하듯"이라고 물어보기
    2. 구조도 직접 그리기: 폰 → GitHub Pages → 익명 로그인 → Firestore종이에 그려서 사진으로 남기기
    3. 약속 상태(open → matched → running → done)를 그림으로 그리기
    4. firestore.rules 4가지 원칙을 내 말로 한 줄씩 쓰기

    2주차 · 작게 고쳐 보기

    목표: 코드를 바꾸고 결과를 예측해서 맞힌다.

    1. 점수 규칙 값(P, RULE, TIERS)을 바꿔 보고 결과를 먼저 예측이 보고서의 포인트 계산기로 예측 연습
    2. 장소 목록(PLACES)에 교내 장소 하나 추가
    3. 글자·색 바꾸기 → 커밋 → 푸시 → 1~2분 뒤 주소에서 확인commit, push, Pages 반영의 흐름을 몸으로 익히기
    4. 일부러 오류 만들어 보기(괄호 하나 지우기)브라우저 개발자 도구(F12) 콘솔에서 오류 읽기

    3주차 · 작은 기능 직접 만들기

    목표: AI에게 시키기 전에 설계를 먼저 쓴다.

    1. 기능 하나 고르기: 예) 주간 랭킹, 내 기록 보기, 약속 취소 버튼
    2. 먼저 종이에 쓰기: 필요한 데이터, 화면, 규칙, 예외 상황이 설계서를 Claude에게 주고 코드를 받으면, 의존이 아니라 협업이 돼요
    3. 받은 코드를 한 줄씩 설명할 수 있을 때까지 읽기
    4. 시험 계정 두 개로 끝까지 시험하고 버그 목록 작성

    4주차 · 설명하고 운영하기

    목표: 3분 발표와 질의응답을 막힘없이.

    1. 3분 발표 대본: 문제 → 해결 → 증거(작동 화면) → 다음 계획
    2. 아래 '발표 예상 질문' 8개에 내 말로 답 쓰기
    3. 시범 운영: 한 반 또는 동아리 10~20명, 1~2주선생님·담임 선생님께 먼저 알리기
    4. 운영 후 느낀 점과 고친 점 기록 → 발표의 마지막 장면

    AI와 함께 배우는 법

    시키는 것에서, 배우는 것으로.

    같은 AI라도 이렇게 물으면 실력이 늘어요. 눌러서 복사해 쓰세요.

    1 · 한 줄씩 설명읽기 도우미
    아래 코드를 한 줄씩 설명해 줘. 고등학생이 이해할 수 있게, 이 줄이 없으면 어떻게 되는지도 알려 줘.
    (코드 붙여넣기)
    2 · 예측 퀴즈예측 연습
    이 코드에서 값을 하나 바꾸면 어떤 일이 생길까? 내가 먼저 예측해 볼 테니, 맞는지 틀린지 채점하고 틀리면 이유를 알려 줘. 정답부터 말하지 마.
    3 · 설계 먼저코드 전에 설계
    새 기능을 만들고 싶어. 코드를 주기 전에 내가 쓴 설계(데이터, 화면, 예외 상황)에 빠진 부분이 있는지 질문으로 먼저 알려 줘.
    4 · 말로 설명 점검설명 시험관
    내가 이 기능을 발표에서 설명할 거야. 면접관처럼 꼬리 질문을 하나씩 해 줘. 내 답이 부정확하면 짚어 줘.
    비밀번호·개인정보는 AI에게 붙여넣지 않기결과는 직접 실행해서 확인하기받은 코드는 설명할 수 있을 때까지 읽기
